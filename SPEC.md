# macsweep — спецификация

Утилита поиска и безопасного удаления мусора на macOS: кэшей, осиротевших данных
удалённых приложений, артефактов сборки, дублей тулчейнов.

Не «ещё один CleanMyMac». Ценность не в интерфейсе, а в **базе знаний** о том, где
macOS и разработческие инструменты прячут восстановимые данные, и в **эвристиках**,
которые отличают «пересоздастся само» от «содержательные данные пользователя».
UI вокруг этого ядра взаимозаменяем и в спеке намеренно вторичен.

Читать вместе с `reference/mac-deep-clean.sh` — работающий bash-прототип, из
которого проект вырос. Он определяет требуемое поведение; всё, что ниже, — как
сделать то же самое быстро, тестируемо и безопасно.

---

## 0. Итог в одном абзаце

Один статически слинкованный бинарник на Go. Правила живут в YAML, а не в коде.
Сканер параллельный, с дедупликацией по inode. Решения принимает отдельный
«движок вердиктов» на предикатах. Удаление — только через системную Корзину
(cgo → `NSFileManager`), никогда через `os.Remove`. Первая фаза — TUI на Bubble Tea.
Вторая — встроенный веб-UI из `embed.FS` поверх того же ядра, без Electron.

---

## 1. Технические решения (приняты, не пересматривать без причины)

| Решение | Почему |
|---|---|
| Go, один бинарник | 8–15 МБ против 90–180 МБ у Electron. Чистильщик диска не должен сам весить как проблема, которую он решает |
| Не Electron / не Tauri на первом этапе | Своё Chromium-окружение отращивает собственные `Cache`/`Code Cache`. Веб-UI получим через `embed.FS` + локальный HTTP, браузер у пользователя уже есть |
| CLI, а не `.app` | CLI наследует Full Disk Access терминала. `.app` требует собственный TCC-грант, подпись Developer ID и нотаризацию — это больше работы, чем вся логика сканирования |
| Правила в YAML | Основной актив проекта. Меняются без пересборки, тестируются на фикстурах, принимаются PR-ами от людей с другими стеками |
| cgo только для Корзины | Единственное место, где нужен Objective-C. Всё остальное — чистый Go |

**Целевая платформа:** macOS 13+, arm64 и amd64. Файловая система APFS.

## 3. Модель данных

```go
// Правило: декларативное описание кандидата на удаление.
type Rule struct {
    ID        string      // "jetbrains-caches", уникален, стабилен
    Group     string      // отображаемая группа
    Paths     []string    // с плейсхолдерами ~, $AS, $CA, $CT, $GC, $DEV
    Glob      string      // альтернатива Paths: шаблон обхода
    Verdict   Verdict     // базовый вердикт до применения предикатов
    When      []Predicate // условия, способные повысить/понизить вердикт
    Note      string      // человеческое пояснение, показывается в UI
    Recovery  string      // как вернуть: "npm install", "пересоздастся при запуске"
    MinSize   int64       // не показывать мельче, байты; 0 = дефолт 50 МБ
    OwnerApp  string      // процесс, который надо закрыть перед удалением
}

type Verdict int
const (
    VerdictSafe   Verdict = iota // приложение пересоздаст само
    VerdictReview                // содержательные данные, решает человек
    VerdictKeep                  // никогда не предлагать
)

// Найденный на диске кандидат.
type Candidate struct {
    RuleID     string
    Path       string
    Bytes      int64     // фактическое место на диске
    Files      int
    ModTime    time.Time
    Verdict    Verdict
    Reasons    []string  // «IDE не установлена», «не менялось 200 дней»
    Blocked    string    // непусто = удалять нельзя, здесь причина
}
```

**`Reasons` обязателен.** Пользователь должен видеть не только «можно удалить»,
но и почему движок так решил. Это же основной инструмент отладки эвристик.

## 4. Схема YAML

```yaml
version: 1
group: JetBrains

rules:
  - id: jetbrains-caches
    paths: ["$CA/JetBrains"]
    verdict: safe
    note: индексы IDE
    recovery: пересоберутся при первом открытии проекта
    owner_app: idea

  - id: jetbrains-orphan-config
    glob: "$AS/JetBrains/*"
    verdict: review            # по умолчанию не трогаем
    note: конфиг и плагины версии IDE
    when:
      - if: not app_installed
        args:
          # из имени папки PyCharm2024.1 вырезается версия,
          # остаток мапится на имя приложения
          strip_version: '[0-9]{4}\.[0-9]+$'
          map:
            IntelliJIdea: IntelliJ IDEA
            IdeaIC: IntelliJ IDEA CE
            PyCharm: PyCharm
            GoLand: GoLand
        then: safe
        reason: IDE не установлена — осиротевший конфиг
    exclude: ["Toolbox", "consentOptions"]

  - id: stale-node-modules
    glob: "$PROJECTS/**/node_modules"
    prune: true                # не заходить внутрь найденного
    verdict: review
    recovery: npm install
    when:
      - if: mtime_older_than
        args: { days: 60 }
        then: safe
        reason: не менялось больше 60 дней
```

### Предикаты (набор фиксирован, реализуются в `internal/engine`)

| Предикат | Аргументы | Смысл |
|---|---|---|
| `app_installed` | `strip_version`, `map` | Приложение с выведенным именем есть в `/Applications`, `~/Applications`, Toolbox |
| `bundle_id_registered` | — | Имя папки похоже на bundle id, и он известен Launch Services |
| `mtime_older_than` | `days` | По самому свежему файлу внутри, не по самой папке |
| `process_running` | `name` | Процесс запущен |
| `path_exists` | `path` | Вспомогательный |
| `larger_than` | `bytes` | Вспомогательный |

Каждый — с префиксом `not`. Правило комбинирует предикаты по И; для ИЛИ пишутся
несколько блоков `when`.

**Определение установленных приложений.** Прототип звал `mdfind` по
`kMDItemCFBundleIdentifier`, и это ненадёжно: Spotlight может быть отключён,
индекс — устаревшим, а том — исключённым из индексации. Правильный источник —
Launch Services:

```
/System/Library/Frameworks/CoreServices.framework/Versions/A/Frameworks/\
LaunchServices.framework/Versions/A/Support/lsregister -dump
```

Разобрать один раз при старте, сложить в мапу bundle id → путь. Если `lsregister`
недоступен — деградировать до обхода `/Applications` и `~/Applications` на глубину 2,
а `mdfind` использовать только как третий запасной вариант. **Ни при каком отказе
этих механизмов вердикт не может стать `safe`** — неизвестность означает `review`.

## 5. Сканер

### Требования

- **Параллельный обход.** Пул воркеров, по умолчанию `min(NumCPU*2, 16)`,
  настраивается. `filepath.WalkDir` без вызова `os.Stat` на каждый вход
  (`DirEntry.Info()` уже несёт нужное).
- **Размер — это `st_blocks * 512`, а не `st_size`.** Иначе разреженные файлы и
  сжатые APFS-файлы считаются неверно. `du` показывает именно занятое место, и
  сравнение с ним — часть приёмки.
- **Дедупликация по `(dev, ino)`.** APFS-клоны и жёсткие ссылки иначе считаются
  многократно. Особенно заметно на симуляторах Xcode и node_modules с хардлинками
  от pnpm. Дедуп — в пределах одного скана, глобально, через конкурентную мапу.
- **Не переходить по символическим ссылкам** и не покидать стартовое устройство
  (проверять `dev`). Firmlinks в macOS иначе уведут в `/System/Volumes/Data`
  и обход зациклится.
- **Пропускать** `.noindex`, смонтированные тома, `/Volumes`, сетевые точки.
- Прогресс — в канал: обработано путей, накоплено байт, текущий путь. TUI и веб
  подписываются на один и тот же канал.
- Отмена — через `context.Context`, обязана срабатывать за доли секунды.

### Ориентир по производительности

Прототип на `du -sk` обходит домашний каталог за 2–5 минут. Цель — **менее 20 секунд**
на том же каталоге на любом Apple Silicon. Если не выходит — узкое место в
последовательном stat, а не в диске.

### Кэш манифеста

`~/Library/Caches/macsweep/manifest.json`, TTL 2 часа, флаг `--rescan`.
Формат версионируется; манифест другой версии игнорируется, а не чинится.

## 6. Корзина

Единственный допустимый способ удаления:

```objc
[[NSFileManager defaultManager] trashItemAtURL:url resultingItemURL:&out error:&err]
```

через cgo. Это даёт настоящую Корзину Finder с работающим «Положить назад» —
чего bash-прототип с `mv ~/.Trash/...` не умеет.

Порядок отказов:

1. `trashItemAtURL:` — основной путь.
2. При ошибке — показать её пользователю и **пропустить элемент**.
3. `os.RemoveAll` не вызывается никогда и ни при каких флагах. В кодовой базе его
   быть не должно; добавить проверку в CI (`grep`-линтер или `forbidigo`).

После каждого прогона писать `~/Library/Caches/macsweep/runs/<timestamp>.json`:
что перенесено, откуда, сколько, каким правилом. Это журнал для разбора
«а почему у меня пропало» и основа будущей команды `macsweep undo`.

## 7. Инварианты безопасности

Это самый важный раздел. Нарушение любого пункта — блокирующий баг.

1. **Dry-run по умолчанию.** Без явного флага удаления процесс не изменяет ФС.
2. **Только через Корзину.** См. выше.
3. **Списки корней.** Обход разрешён только под `~` и явно перечисленными корнями
   из конфигурации. Всё вне — игнорируется, даже если правило указывает туда.
4. **Жёсткий denylist**, перекрывающий любое правило: `~/Documents`, `~/Desktop`,
   `~/Pictures`, `~/Movies`, `~/Music`, `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.config`,
   `~/.Trash`, любые `.git`, `*.photoslibrary`, `*.sparsebundle`, ключи, keychain,
   каталоги с исходниками. Проверка — на абсолютном пути после `filepath.EvalSymlinks`.
5. **Никогда не удалять данные запущенного приложения.** Electron-приложения на
   выходе перезаписывают свои папки, и удаление под ними бессмысленно и опасно.
   Проверять до, а не после.
6. **Неизвестность = `review`.** Любой сбой предиктора понижает вердикт, а не повышает.
7. **Ничего вне манифеста.** Удаляется ровно то, что показано в отчёте, и ничего,
   что появилось на диске между сканом и удалением: перед `trashItem` сверять
   `(dev, ino)` и mtime с записанными.
8. **Пути с пробелами, юникодом и переводами строк** обязаны работать. В тестах —
   фикстуры с такими именами.

## 8. Интерфейс командной строки

```
macsweep                     скан и отчёт, ничего не меняет
macsweep --tui               интерактивный выбор (по умолчанию, если есть tty)
macsweep --json              машиночитаемый отчёт в stdout
macsweep --clean             перенести отмеченное в Корзину
macsweep --clean --yes       без интерактивного подтверждения (для скриптов)
macsweep --group jetbrains   ограничить группами
macsweep --min-size 100MB
macsweep --rescan
macsweep --rules ./rules     свои правила вместо вкомпилированных
macsweep --explain <path>    почему этот путь получил такой вердикт
macsweep --web               фаза 2: поднять локальный UI
```

`--explain` не украшение: при декларативных правилах это основной способ понять
поведение движка.

Коды возврата: `0` — успех, `1` — ошибка, `2` — часть элементов пропущена.

## 9. TUI (фаза 1)

Bubble Tea + Lip Gloss. Три экрана:

**Скан.** Прогресс-бар, счётчик путей, текущий каталог, накопленный размер.
Отменяется по `q`/`Ctrl-C` мгновенно.

**Результаты.** Дерево групп, внутри — кандидаты, отсортированные по убыванию
размера. Колонки: чекбокс, размер, путь (с `~`), вердикт значком. Панель снизу —
`note`, `recovery` и `reasons` выделенного элемента.

Клавиши: `↑↓`/`jk` навигация, `space` отметить, `a` вся группа, `tab` свернуть,
`e` объяснить (`--explain` для элемента), `/` фильтр, `d` удалить отмеченное,
`?` помощь, `q` выход.

**Подтверждение.** Итог по группам, суммарный размер, список запущенных приложений,
которые надо закрыть. Отмеченные `review` перечисляются отдельно и требуют
второго подтверждения.

Цвет — только как дополнение к значку: `✓` safe, `?` review. Всё читается в
монохроме и при `NO_COLOR`.

## 10. Веб-UI (фаза 2)

Тот же бинарник, флаг `--web`: HTTP на `127.0.0.1` на случайном порту, статика из
`embed.FS`, открытие браузера. Слушать **только** loopback, токен в URL, выключаться
по закрытию вкладки (heartbeat).

- Sunburst-диаграмма на d3 — тот же взгляд, что в DaisyDisk, только с наложенными
  вердиктами: safe зелёным, review жёлтым, keep серым.
- Клик по сектору — вход внутрь, хлебные крошки, боковая панель с `reasons`.
- API: `GET /api/scan` (SSE с прогрессом), `GET /api/candidates`,
  `POST /api/trash` с телом-списком путей и их `(dev, ino, mtime)`.

Ядро (`scan`, `engine`, `trash`) от UI не зависит и о нём не знает. Если по коду
поползут импорты `internal/tui` в `internal/engine` — архитектура сломана.

## 11. Тестирование

**Фикстуры вместо реальной ФС.** `testdata/fixtures/<case>/` — макет домашнего
каталога, собираемый скриптом (разреженные файлы нужного размера, чтобы
репозиторий не распухал). Тест подменяет `HOME` и корни, гоняет скан, сравнивает
с золотым JSON.

Обязательные сценарии:

- Осиротевший конфиг JetBrains при отсутствующей IDE → `safe`.
- Тот же конфиг при установленной IDE → `review`.
- `node_modules` возрастом 200 дней → `safe`; возрастом 3 дня → `review`.
- Жёсткие ссылки и APFS-клоны не считаются дважды.
- Символическая ссылка наружу дерева не уводит обход.
- Путь из denylist не появляется в кандидатах, даже если правило его указывает.
- Запущенное приложение блокирует удаление своих данных.
- Имена с пробелами, кириллицей, эмодзи и переводом строки.
- Отказ `lsregister` не превращает `review` в `safe`.

**Тест на соответствие `du`.** Отдельный, помеченный `-tags manual`: считает
размер каталога сканером и `du -sk`, требует расхождения меньше 2%. Не в CI,
потому что зависит от машины, но запускается перед релизом.

### Грабли, найденные в прототипе — не наступать повторно

- `GROUPS` в bash — служебная переменная (список групп пользователя), присваивание
  молча игнорируется. Цикл крутился по значению `0`, отчёт выходил пустым, ошибок
  не было. В Go это невозможно, но урок общий: **пустой результат обязан быть
  отличим от отсутствия результата**. Если скан не нашёл ни одного кандидата в
  группе, где ожидались правила, — это предупреждение в лог, а не тишина.
- В `${var/#pattern/~}` тильда в замене раскрывается в путь домашнего каталога.
  Форматирование путей — отдельная функция с тестом.
- `du` без дедупа по inode завышает размеры на каталогах с хардлинками.

## 12. Права, подпись, распространение

- Полный скан `~/Library` требует **Full Disk Access**. У CLI он наследуется от
  терминала. При запуске проверять доступность `~/Library/Application Support` и,
  если отказ, выводить внятную инструкцию: Системные настройки → Конфиденциальность
  и безопасность → Full Disk Access → добавить свой терминал.
- Релизы — `goreleaser`, бинарники под arm64 и amd64, плюс Homebrew tap.
- Подписывать Developer ID и нотаризовать имеет смысл только когда появится `.app`.
  Для CLI из Homebrew это не требуется.
- Телеметрии нет. Сетевых обращений нет вообще — это проверяется тестом.

## 13. Этапы

**M1 — ядро.** Загрузка YAML, параллельный сканер с дедупом, движок предикатов,
`--json`, покрытие фикстурами. Без UI, без удаления. Проверка: вывод совпадает с
`mac-deep-clean.sh` на том же каталоге, работает под 20 секунд.

**M2 — удаление.** cgo-обёртка Корзины, инварианты безопасности, журнал прогонов,
`--clean --yes`.

**M3 — TUI.** Три экрана, `--explain`.

**M4 — правила.** Полный перенос всех групп прототипа в YAML, документация схемы,
README с инструкцией «как добавить своё правило».

**M5 — веб-UI.** `embed.FS`, sunburst, SSE-прогресс.

**M6 — `macsweep undo`.** Восстановление по журналу прогона.

Каждый этап заканчивается работающим бинарником. M1 без M2 уже полезен как
диагностика.

## 14. Чего проект не делает

- Не чистит системные каталоги вне `~` (`/Library`, `/private/var`). Нужен sudo,
  выгода мала, риск велик.
- Не удаляет приложения. Показать размер `/Applications/Xcode.app` — да, удалить — нет.
- Не трогает локальные снапшоты Time Machine, Docker.raw и кэш Google Drive:
  их надо сжимать штатными средствами, а не удалять файлом. Показывать с подсказкой
  и точной командой.
- Не «оптимизирует» и не «ускоряет» систему. Никаких очисток RAM и починок прав.
- Не работает на Linux и Windows. Правила и системные вызовы завязаны на macOS.

2. Реализовать `internal/rules`: типы, загрузку YAML, валидацию (неизвестный
   предикат, дубль `id`, путь вне разрешённых корней — ошибки загрузки, не
   предупреждения).
3. Реализовать `internal/scan` по требованиям раздела 5, с бенчмарком.
4. Реализовать `internal/engine` с шестью предикатами и накоплением `Reasons`.
5. Перенести в `rules/30-jetbrains.yaml` и `rules/40-toolchains.yaml` соответствующие
   части прототипа — как проверку выразительности схемы. Остальные группы позже.
6. Собрать фикстуры и тесты из раздела 11.
7. `cmd/macsweep` с флагами `--json`, `--rules`, `--rescan`, `--min-size`, `--explain`.

Удаления на этом этапе нет вообще — ни кода, ни флага. Это осознанно:
сначала пусть научится правильно решать, потом получит право действовать.
